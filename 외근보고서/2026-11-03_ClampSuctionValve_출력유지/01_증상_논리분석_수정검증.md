# Clamp Suction Valve 출력 ON 유지 — 증상·논리·검증 계획

> 작업 주간: 2026-11-02 ~ 2026-11-06  
> 구분: 출력 제어 / I/O 진단  
> 상태: **코드 조건 확인 / 실제 ON 원인 미확정**

## 1. 현상

장비 부팅 직후부터 Clamp Suction Valve Open 출력이 ON으로 유지되며, **모터 OFF 상태에서도 출력이 유지**된다는 현상이 보고되었다. 부팅 상태와 출력 상태의 관계를 확인하는 것이 쟁점이다.

확인된 사실은 **출력이 ON으로 표시되는 현상**과 **해당 출력을 구성하는 소프트웨어 조건식**이다. 이 정보만으로 실제 밸브가 움직였는지, 설비 설계상 모터 OFF가 반드시 출력 OFF를 의미하는지까지 확정할 수는 없다.

## 2. 확인한 제어 구조

분석 대상은 TL 기종 출력 처리 구간과 전역 I/O 정의이다. 공개본에서는 회사 원본 소스를 복제하지 않고 판정 관계만 기록한다.

~~~text
ClampSuctionValveOpen
    = negDO2
      OR (ValveCharactarization_SQp_act != 0)
~~~

- **negDO2 경로:** 축/기계 동작에서 발생하는 정방향·역방향 출력 요구 중 해당 신호의 출처 확인 필요
- **ValveCharactarization 경로:** 밸브 특성화 관련 상태가 0이 아닐 때 독립적으로 출력 요청이 성립하는 경로
- **최종 출력:** 두 경로 중 하나라도 참이면 출력 요구가 유지된다

즉 **모터 OFF 여부를 직접 검사하는 조건이 위 OR 식에 보이지 않는다.** 그러나 이 구간 이외의 인터록·출력 매핑·전장 동작이 있는지는 추가 확인해야 한다.

## 3. 판단 견해 — 원인을 세 계층으로 분리

### A. 제어 명령이 유지되는 경우
- 부팅 초기화 이전/이후에 negDO2 또는 특성화 상태가 0이 아닌지
- 관련 상태가 RETAIN·복귀·모드 전환에 의해 재설정되는지
- 정상 동작 후 OFF 복귀 분기가 실제 호출되는지

### B. 논리 값과 최종 매핑의 차이
- PLC의 논리 출력과 최종 I/O 매핑의 일치 여부
- 활성 High/Low, 부정 논리, 다른 태스크의 중복 기록 여부
- 모터 OFF 상태에서 해당 밸브의 출력 허용 정책과 전장 설계의 관계

### C. 소프트웨어와 실제 하드웨어의 차이
- PLC DO 상태와 현장 출력 단자, 릴레이·솔레노이드 상태가 일치하는지
- 출력이 논리상 OFF인데 실물이 동작한다면 배선·출력단 쪽 문제로 분기

**현재 우선 가설:** OR 조건의 한 갈래가 초기화 또는 복귀 중 유지될 수 있다. 다만 어느 변수가 실제 원인인지는 측정 전 확정할 수 없다.

## 4. 검증 순서

1. 전원 투입 직후·모터 OFF·모터 ON·관련 기능 실행/종료의 동일 조건에서 두 입력 갈래와 최종 논리 출력을 동시에 기록한다.
2. 최종 PLC I/O와 현장 출력 상태가 일치하는지 대조한다.
3. 기계 설계상 모터 OFF 시 밸브의 기대 상태 및 안전 요구를 전장·기계 담당과 확인한다.
4. 문제가 소프트웨어 값 유지라면 초기화, 상태 복귀, 명령 소유자 및 해제 위치를 추적한다.
5. 수정 후 부팅·정상 운전·모터 정지·전원 재투입의 재발 시험을 수행한다.

## 5. 수정 방향(제안, 미적용)

- 출력이 의도하지 않게 유지된다면 **명령의 소유자와 해제 조건**을 명시해 경쟁 기록을 방지한다.
- 단순히 모터 OFF 조건을 출력식에 삽입하는 것은 안전한 수정이라고 보장할 수 없다. 밸브의 정지·배압·보호 동작 의도를 검증한 뒤 변경한다.
- 로그 또는 진단 표시에서 '어느 OR 경로가 ON을 요청했는지' 확인 가능하게 개선할 수 있다.

**결론:** 출력 ON 유지 경로를 코드상 분해했으나 근본 원인 및 실제 수정 적용은 미확정. **현장 변수·최종 DO·실물 일치 검증이 다음 단계**이다.
