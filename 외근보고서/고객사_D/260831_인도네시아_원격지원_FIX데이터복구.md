# 인도네시아 현장 원격지원 - FIX 데이터 복구 및 설정 정합성 점검

## 1. 개요

2026년 8월 31일부터 9월 1일까지 인도네시아 현장 장비를 대상으로 원격 기술지원을 진행하였다.

이번 건은 모니터 업그레이드 이후 장비를 재기동했을 때 FIX/Recipe 관련 알람이 발생하고, 일부 수동동작이 정상적으로 수행되지 않는 문제를 추적한 사례이다.

단순히 하나의 파라미터가 잘못된 문제가 아니라 다음 두 영역이 동시에 겹쳐 있었다.

```text
1. 구형/신형 FIX 데이터 구조 차이 및 설정값 정합성 문제
2. FIX/Recipe 데이터 저장 영역의 정상 유지 여부 문제
```

따라서 알람만 제거하는 방식이 아니라 저장 → 재부팅 → 재로딩 → 실제 동작 확인의 순서로 범위를 나누어 점검하였다.

---

## 2. 현장 증상

현지 엔지니어가 전달한 초기 증상은 다음과 같았다.

```text
- 재부팅 후 Default FIX 관련 알람 발생
- Recipe 데이터가 유효하지 않다는 알람 발생
- 재기동 후 일부 설정값이 정상적으로 유지되지 않는 것으로 보임
- Manual 상태가 정상적으로 활성화되지 않는 경우 발생
- 노즐 전진 불가 / 노즐 후진 저속 동작
- Mold Adjust 전진·후진 동작 불가
```

초기에는 FIX 파일 자체의 문제처럼 보였으나, 재부팅 전후 상태가 달라지는 점 때문에 파일 내용뿐 아니라 데이터 저장 영역까지 함께 확인할 필요가 있었다.

---

## 3. 문제 분리

이번 문제는 한 번에 하나의 원인으로 설명하기 어려웠기 때문에 아래와 같이 분리하였다.

### 3.1 FIX 데이터 구조 문제

모니터 및 프로젝트 버전 변경 과정에서 신형 환경에 추가된 설정 항목이 존재하였다.

기존 FIX 데이터를 그대로 적용하면 구형 데이터에 존재하지 않는 신규 파라미터가 정상 기본값을 유지하지 못하거나, 장비 옵션과 맞지 않는 값이 들어갈 가능성이 있었다.

따라서 기존 FIX 파일을 그대로 덮어쓰는 방식보다 다음 기준이 필요했다.

```text
신형 FIX 구조를 기준으로 유지
→ 구형 FIX에서 실제 필요한 설정값만 이식
→ 신형에서 추가된 항목은 신형 기본값 유지
```

이 과정에서 FIX 파일은 단순 CSV 값 목록이 아니라 장비 버전과 옵션 구조에 종속된 설정 데이터라는 점을 확인하였다.

### 3.2 데이터 저장 영역 문제

FIX와 Recipe를 정상적으로 로딩한 뒤에도 재부팅 후 동일 증상이 반복되었다.

따라서 현재 메모리에 값이 정상적으로 보이는지와 별개로, 저장된 데이터가 재기동 후 다시 정상적으로 읽히는지 확인하였다.

점검 기준은 다음과 같았다.

```text
FIX Load 성공
→ Recipe Load 성공
→ 저장
→ 장비 재부팅
→ FIX/Recipe 상태 재확인
```

재부팅 시점에서 문제가 반복되는 경우 저장 영역 또는 기존 데이터 잔존 상태를 의심할 수 있기 때문에 관련 파티션을 정리한 뒤 다시 데이터를 구성하는 방향으로 조치하였다.

---

## 4. 조치 과정

### 4.1 기존 데이터 상태 확인

먼저 현지 엔지니어와 화면을 공유하면서 현재 Rack FIX 및 주요 파라미터가 정상적으로 표시되는지 확인하였다.

한 번의 로딩 결과만 보고 정상으로 판단하지 않고 재부팅 후 동일 값이 유지되는지 반복 확인하였다.

### 4.2 저장 영역 초기화 및 재구성

기존 데이터가 남아 있는 상태에서 파일만 반복 교체하면 저장영역 문제와 FIX 내용 문제를 구분하기 어렵다.

따라서 관련 저장영역을 초기화하고 필요한 데이터를 다시 설치하여 기준 상태를 만들었다.

핵심 목적은 다음과 같다.

```text
기존 잔존 데이터 제거
→ 정상 기준 데이터 재설치
→ FIX/Recipe 재적용
→ 재부팅 후 유지 여부 확인
```

### 4.3 신형 기준 FIX 적용

구형 FIX 파일을 그대로 사용하는 대신 신형 구조를 기준으로 설정값을 재구성하였다.

구형 장비에서 사용하던 값 중 실제 동작에 필요한 항목은 이식하되, 신형에서 추가된 설정은 무조건 구형 값으로 덮어쓰지 않았다.

이 방식으로 FIX 데이터 구조 차이로 인해 발생할 수 있는 설정 누락을 줄였다.

### 4.4 실제 장비 동작 기준 재검증

FIX/Recipe 알람이 사라지는 것만으로 작업을 종료하지 않았다.

이후 다음 수동동작을 다시 확인하였다.

```text
- Nozzle Forward
- Nozzle Backward
- Mold Adjust Forward / Backward
- Manual Enable 상태
```

이 과정에서 저장 문제와 별개로 장비 옵션 및 보호 관련 설정값이 실제 동작에 영향을 주고 있음을 확인하였다.

일부 파라미터는 신형 환경에서 기존 장비 옵션에 맞게 다시 설정해야 했다.

---

## 5. 원인 정리

이번 문제는 다음과 같이 두 단계로 정리할 수 있다.

| 구분 | 문제 | 영향 |
|---|---|---|
| 데이터 구조 | 구형 FIX와 신형 FIX의 항목 및 기본값 차이 | 신규 옵션 설정 누락 또는 부적절한 값 적용 가능 |
| 저장/복구 | 재부팅 후 FIX/Recipe 상태가 정상 유지되지 않음 | Default FIX / Invalid Recipe 계열 알람 반복 |
| 장비 설정 | 신형 환경의 옵션·보호 관련 설정값 불일치 | 노즐 및 Mold Adjust 등 수동동작 이상 |

즉, FIX 파일 하나만 교체한다고 해결되는 문제가 아니었다.

```text
파일 구조 정합성
+
저장 영역 정합성
+
실제 장비 옵션 설정
```

세 영역을 각각 확인해야 했다.

## 6. 결과

저장영역을 정리하고 신형 구조를 기준으로 FIX/Recipe 데이터를 다시 구성한 뒤, 반복 재부팅을 통해 상태를 확인하였다.

그 결과 초기의 Default FIX 및 Recipe 관련 알람은 정리할 수 있었다.

이후 남은 수동동작 이상은 데이터 저장 문제와 분리하여 장비 옵션 및 동작 설정 영역으로 범위를 좁힐 수 있었다.

최종 생산 검증은 현지에서 금형을 설치한 상태로 추가 확인하기로 하였다.

---

## 7. 이번 대응에서 정리된 기준

### 7.1 버전이 바뀐 FIX는 단순 덮어쓰지 않는다

구형 FIX와 신형 FIX의 구조가 다를 수 있으므로 신형 빈 구조를 기준으로 필요한 값만 이식하는 편이 안전하다.

### 7.2 저장 성공과 현재 값 표시는 다른 문제다

현재 화면에 값이 정상적으로 보이는 것만으로 데이터 저장이 정상이라고 판단할 수 없다.

```text
Load
→ Save
→ Reboot
→ Reload 상태 확인
```

까지 확인해야 저장 문제를 배제할 수 있다.

### 7.3 알람 복구 후 실제 액추에이터 동작을 별도로 확인한다

FIX/Recipe 알람이 없어져도 옵션 파라미터 불일치가 남아 있으면 노즐, 금형조정 등 실제 장치의 속도 또는 동작 여부가 달라질 수 있다.

따라서 검증 순서는 다음과 같이 잡는 것이 효율적이었다.

```text
데이터 저장 정상화
→ FIX/Recipe 알람 확인
→ Manual Enable 확인
→ 개별 액추에이터 동작 확인
→ 금형 장착 후 생산 테스트
```

---

## 8. 결론

이번 인도네시아 원격지원 건은 모니터 업그레이드 이후 발생한 FIX/Recipe 문제를 단순 파라미터 오류로 보지 않고, 데이터 구조와 저장영역, 실제 장비 설정을 분리하여 추적한 사례이다.

특히 재부팅 전에는 정상처럼 보이지만 재부팅 후 다시 문제가 발생하는 경우 현재 메모리의 값보다 데이터의 저장·복구 경로를 먼저 검증해야 한다는 점을 확인하였다.

또한 장비 버전이 변경될 때에는 과거 FIX 전체를 그대로 이식하기보다 새로운 구조를 기준으로 기존 설정을 필요한 범위만 이식해야 신규 옵션과 기본값의 정합성을 유지할 수 있다.
