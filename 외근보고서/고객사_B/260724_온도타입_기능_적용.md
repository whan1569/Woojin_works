# 고객사 B 원격지원 진행 보고서

작성일: 2026-07-24

## 1. 개요

본 보고서는 고객사 B 설비 원격지원 과정에서 수행한 원격 연결 환경 구성, 온도카드 센서 타입 변경 기능의 이상 현상 확인, SW 원인 분석 및 수정 내용을 정리한 것이다.

기존 원격지원에서는 설비 프로그램 내 원격 접속용 ETH 포트가 개방되어 있지 않아 실제 설비 분석 단계까지 진행하지 못하였다.

이번 작업에서는 사전에 준비된 네트워크 설정을 기준으로 현장 설비와 원격지원 PC 간 통신 환경을 구성하고, VPN을 통해 Automation Studio를 현장 PLC에 연결하였다.

원격 접속 후 실제 설비에서 온도카드 센서 타입 변경 기능을 동작시키며 관련 변수와 기능 블록의 상태를 직접 확인하였고, 카드 설정값이 실제로 적용되지 않는 SW 오류를 확인하여 수정하였다.

## 2. 작업 목적

이번 원격지원의 목적은 다음과 같다.

1. 현장 설비와 원격지원 PC 간 통신 환경 구성
2. VPN을 통한 Automation Studio 온라인 연결
3. 온도카드 센서 타입 변경 기능의 실제 동작 확인
4. 설정값과 실제 카드 적용값 간 불일치 원인 분석
5. SW 수정 및 현장 설비 적용
6. 수정 후 기능 정상 동작 여부 검증

## 3. 원격지원 진행 내용

### 3.1 원격 연결 환경 구성

현장 설비에 직접 접속하여 상태를 확인하기 위해 원격지원 PC와 현장 설비 간 네트워크 환경을 구성하였다.

양측 네트워크가 직접 연결되지 않는 환경이므로 원격 연결을 위한 라우팅 설정을 적용하고, 현장과 원격지원 측에서 동일한 접속 포트를 사용할 수 있도록 통신 조건을 맞추었다.

이후 VPN을 이용하여 양측 네트워크를 연결하고 Automation Studio에서 현장 PLC에 온라인 접속하였다.

진행한 내용은 다음과 같다.

* 현장 PC 및 설비 측 네트워크 상태 확인
* 원격지원 PC와 현장 설비 간 IP 통신 경로 구성
* 양측 접속 포트 설정 확인
* VPN 연결 및 통신 상태 확인
* Automation Studio 온라인 접속
* PLC 프로그램 및 온라인 변수 모니터링 환경 구성

확인 결과 Automation Studio에서 현장 PLC에 정상적으로 접속되었으며, 실제 설비 프로그램의 동작 상태를 원격으로 확인할 수 있었다.

### 3.2 온도카드 센서 타입 변경 현상 확인

원격 접속 후 현장에서 요청한 온도카드 센서 타입 변경 기능을 실제로 실행하였다.

온도카드 센서 타입을 변경할 경우 설정값을 저장하는 `HT_FIX.Cardtype[]` 배열에는 선택한 타입이 정상적으로 반영되었으나, 실제 카드 적용 결과를 나타내는 `actCardtype[]` 배열은 갱신되지 않았다.

확인된 동작은 다음과 같다.

```text
센서 타입 변경 요청
        ↓
HT_FIX.Cardtype[] 설정값 변경
        ↓
온도카드 설정값 쓰기 요청
        ↓
카드 쓰기 정상 완료 실패
        ↓
actCardtype[] 미갱신
```

이에 따라 화면과 내부 설정값에서는 센서 타입이 변경된 것처럼 보이지만, 실제 온도카드에는 해당 설정이 적용되지 않는 상태임을 확인하였다.

### 3.3 기존 기능 상태 확인

해당 기능은 프로그램 내에 다음과 같은 구성 요소가 존재하고 있었다.

* 센서 타입 선택 화면
* 센서 타입 설정 변수
* 카드별 타입 변경 요청
* 전체 카드 일괄 변경 요청
* 실제 적용 상태 확인 배열
* 온도카드 설정값 쓰기 로직

그러나 기존 설비 운전에서는 온도센서 타입을 변경할 필요가 거의 없었으며, 주로 설정온도만 변경하여 사용하고 있었다.

이로 인해 센서 타입 변경 기능은 화면과 코드상으로는 존재했지만 실제 카드 적용까지 정상적으로 이루어지는지 충분히 검증되지 않았던 것으로 판단된다.

이번 원격지원을 통해 해당 기능이 실제로는 정상 완료되지 않는 상태임을 확인하였다.

## 4. SW 분석 및 조치 내용

### 4.1 SW 동작 구조 확인

온도카드 센서 타입 변경 기능은 상태 머신을 통해 여러 PLC 스캔에 걸쳐 실행되는 구조였다.

```text
STEP_INIT
채널명 및 설정값 준비
        ↓
STEP_WRITE
AsIOAccWrite 실행
        ↓
STEP_DONE
쓰기 결과 확인 및 actCardtype[] 갱신
```

`STEP_INIT`에서 카드 주소, 채널명 및 센서 타입값을 준비한 뒤 다음 PLC 스캔에서 `AsIOAccWrite` 기능 블록을 실행하고 있었다.

카드 쓰기가 정상 완료되어 `ERR_OK` 상태가 확인된 경우에만 `actCardtype[]`가 갱신되는 구조였다.

### 4.2 원인 분석

기존 코드에서는 센서 타입 쓰기 채널명을 함수 내부 지역변수에 저장한 후 해당 주소를 `AsIOAccWrite1.pChannelName`에 전달하고 있었다.

수정 전 구조는 다음과 같다.

```c
static BOOL PrepareSensorWriteByIndex(UINT index, USINT reqType)
{
    char token[10];
    char chName[50];

    GetChannelNameByIndex(index, token, chName);

    AsIOAccWrite1.pChannelName =
        (unsigned long)chName;

    return 1;
}
```

`AsIOAccWrite1.pChannelName`에는 채널명 문자열 자체가 복사되는 것이 아니라 채널명이 저장된 메모리 주소가 전달된다.

그러나 `chName`은 함수 내부 지역변수이므로 `PrepareSensorWriteByIndex()` 함수가 종료되면 해당 변수의 유효기간도 종료된다.

실제 `AsIOAccWrite()` 실행은 다음 PLC 스캔의 `STEP_WRITE` 단계에서 이루어지므로, 기능 블록 실행 시점에는 이미 유효하지 않은 채널명 주소를 참조하게 된다.

이에 따라 카드 쓰기가 정상적으로 완료되지 않았으며, 쓰기 성공 이후에 실행되는 `actCardtype[]` 갱신도 이루어지지 않았다.

확인된 원인은 다음과 같다.

> 여러 PLC 스캔에 걸쳐 실행되는 비동기 기능 블록에 함수 지역변수의 주소를 전달하여, 실제 온도카드 쓰기 시점에 채널명 포인터가 유효하지 않은 상태가 되었다.

### 4.3 SW 수정 내용

함수 내부 지역변수로 선언된 `chName`을 제거하고, PLC 태스크 실행 중 값이 유지되는 기존 `_LOCAL sChName` 변수를 사용하도록 수정하였다.

수정 전 코드는 다음과 같다.

```c
char chName[50];

memset(chName, 0, sizeof(chName));

GetChannelNameByIndex(
    index,
    token,
    chName);

AsIOAccWrite1.pChannelName =
    (unsigned long)chName;
```

수정 후 코드는 다음과 같다.

```c
memset(sChName, 0, sizeof(sChName));

GetChannelNameByIndex(
    index,
    token,
    sChName);

AsIOAccWrite1.pChannelName =
    (unsigned long)sChName;
```

수정 시 센서 타입 매핑값, 온도카드 배열 순서, 카드별 변경 및 일괄 변경 상태 머신은 변경하지 않았다.

비동기 기능 블록이 실제 쓰기를 완료할 때까지 채널명 데이터가 유지되도록 변수의 유효기간 문제만 최소 범위로 수정하였다.

## 5. 작업 결과

수정 프로그램을 현장 설비에 적용한 후 Automation Studio 온라인 상태에서 센서 타입 변경 기능을 다시 시험하였다.

확인 결과 다음 항목이 정상적으로 동작하였다.

1. 센서 타입 변경 요청 정상 발생
2. `HT_FIX.Cardtype[]` 설정값 정상 변경
3. 온도카드 설정 채널 정상 지정
4. `AsIOAccWrite` 기능 블록 정상 완료
5. `actCardtype[]` 적용값 정상 갱신
6. 설정값과 실제 적용값 정상 동기화
7. 온도카드 센서 타입 변경 기능 정상 동작

정상 동작 시 다음 관계가 유지되는 것을 확인하였다.

```c
actCardtype[index]
    == HT_FIX.Cardtype[index];
```

기존에는 화면과 관련 변수만 존재하고 실제 카드 쓰기가 정상 완료되지 않았으나, 이번 수정을 통해 센서 타입 변경 기능이 실제 설비에서 사용할 수 있는 상태로 정상화되었다.

## 6. 원격지원 과정에서 확인된 사항

이번 작업을 통해 원격지원 전 네트워크 환경과 프로그램 설정을 사전에 준비하는 것이 중요함을 확인하였다.

특히 구형 설비는 원격지원용 통신 포트가 기본적으로 구성되어 있지 않을 수 있으므로, 원격지원 전에 다음 항목을 확인할 필요가 있다.

* 설비 프로그램 내 원격 접속용 ETH 포트 설정
* 현장과 원격지원 측 IP 대역
* VPN 연결 상태
* 양측 접속 포트 일치 여부
* 현장 LAN 케이블 연결 위치
* Automation Studio 온라인 접속 가능 여부
* 기존 프로그램 백업 및 원복 절차

또한 비동기 기능 블록에 문자열 또는 데이터 주소를 전달하는 경우, 기능 블록 완료 시점까지 해당 변수의 유효기간이 유지되는지 확인할 필요가 있다.

향후 유사 코드 검토 시에는 다음 항목을 점검한다.

* 기능 블록에 함수 지역변수 주소가 전달되는지
* 기능 블록 호출이 여러 PLC 스캔에 걸쳐 수행되는지
* 완료 상태 확인 전 데이터가 변경되거나 소멸하는지
* 포인터가 참조하는 변수가 `_LOCAL`, `_GLOBAL` 또는 정적 저장 영역인지


## 7. 결론

이번 원격지원에서는 라우팅 설정 및 VPN을 이용하여 현장 설비와 원격지원 PC 간 통신 환경을 구성하고, Automation Studio를 현장 PLC에 직접 연결하였다.

온라인 상태에서 센서 타입 변경 기능의 실행 흐름과 관련 변수를 확인한 결과, 설정값은 정상적으로 변경되지만 실제 온도카드 쓰기가 완료되지 않아 `actCardtype[]`가 갱신되지 않는 문제를 확인하였다.

원인은 여러 PLC 스캔에 걸쳐 실행되는 `AsIOAccWrite` 기능 블록에 함수 지역변수의 주소를 전달한 것으로, 실제 기능 블록 실행 시점에는 채널명 포인터가 유효하지 않은 상태가 되고 있었다.

채널명 저장 변수를 함수 지역변수에서 `_LOCAL` 변수로 변경하여 실제 카드 쓰기 완료 시점까지 데이터가 유지되도록 수정하였다.

수정 후 현장 설비에서 온도카드 센서 타입 설정값과 실제 적용값이 정상적으로 동기화되는 것을 확인하였다.

이번 작업을 통해 기존에 프로그램과 화면상으로만 존재하고 실제로는 정상 사용할 수 없었던 온도카드 센서 타입 변경 기능을 현장 설비에서 실제 사용 가능한 기능으로 정상화하였다.
