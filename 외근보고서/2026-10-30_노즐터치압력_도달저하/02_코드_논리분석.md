# 02. 코드 논리 분석 — 노즐 압력 형성

> 사건 ID: NOZZLE-PRESSURE-20261030
> 기준 코드: `iu_con/iu_con.c`, `iu_con/ax_func.c` (제공된 소스의 정적 검토)
> 상태: 코드상 후보 경로 확인 / 현장 실행 분기 미확정
> 회사 원본 코드는 공개하지 않고 위치·변수와 동작 논리만 기록

## 1. 노즐 축의 실제 압력값 생성

`AXdat[S_IU].Ap`는 전용 노즐 압력센서 사용 옵션에 따라 다음 두 원본 중 하나를 사용한다.

- 전용 센서 사용: 노즐 압력 아날로그 입력 `PhyIn.ApDig` → 스케일링 → `Ap`
- 전용 센서 미사용: `PUdat[AXdat[S_IU].PmpNr].Ap`에서 펌프 압력 복사

관련 코드: `iu_con.c` 약 317~327행.

**검증상 의미:** 노즐 압력 표시가 노즐 실린더의 실제 유지·형성압력을 직접 측정했다고 가정할 수 없다.

## 2. 압력 지령의 분기

노즐 일반 전진 `F_STEP_NORMAL_MOVE_NEG`에서는 위치·중간정지 조건에 따라 다음 지령을 선택한다.

- 일반 전진 압력: `IU_PAR.NEG.Sp`
- 노즐 접촉/보호 단계 압력: `IU_PAR.NEG.SpNP`
- 현재 실제 축 압력 지령: `AXdat[S_IU].Sp_act`

또한 `AXdat[S_IU].PmpReq.Sp_scal` 등은 전진 시 펌프 측으로 전달되는 스케일된 압력 요구값을 구성한다. 어떤 압력 지령과 펌프 우선순위가 실제 출력으로 선택되는지는 펌프 제어 태스크까지 추적해야 한다.

**가능한 분기:** 레시피에서 175bar로 보이는 값이 있어도 해당 STEP에서 `Sp_act`가 175bar인지 확인 전에는 '175bar를 실제로 지령했다'고 말할 수 없다.

## 3. 전진·승압 완료에 관련된 경로

- 위치센서 경로의 일반 전진: 위치 허용범위 + `Ap >= SpNP - Sptol` 또는 위치 + `negDI1`로 승압 지연에 진입할 수 있다.
- 디지털 센서 경로: 센서 입력 또는 압력 판정으로 승압 지연에 진입한다.
- `SbNozzleBoostPressure` 옵션이 활성화되면 추가 승압 STEP(40)에 진입할 수 있으며 여기서는 `Ap >= SpNP - Sptol`과 `Ap >= IU_FIX.GEN.Ssp` 두 압력 조건을 함께 요구한다.
- 승압 지연 이후 `StopMoveNeg()`가 축의 압력/유량 요청을 0 처리하고, 정상 종료는 `ExitMoveNeg()`에서 전진완료 축 상태를 설정할 수 있다.

따라서 **실제 도달압력 141bar라고 보고됐다는 사실만으로** 어느 시점에 완료되었는지, 허용오차가 무엇인지, 어떤 센서 입력으로 종료했는지 알 수 없다.

## 4. 완료 이후 모니터링과의 관계

`tk1i.c`에는 자동·반자동 + 전진완료 + 모니터링 ON에서 압력 상·하한 감시가 있다. 이 결과가 `alarm.c`의 노즐압력 이상 알람(기본 AUTOSTP)으로 연결된다.

이 감시 기능은 **최초 전진 중 압력을 형성하게 만드는 제어 기능이 아니다.** 따라서 감시 ON/OFF 여부만으로 최초 압력 141bar 제한 원인을 설명할 수 없다.

## 5. 코드 원인과 유압 원인의 구분

| 관찰 | 먼저 조사할 곳 |
| --- | --- |
| `Sp_act`가 목표 175bar에 못 미침 | 단계별 지령 분기, 설정값·위치·중간정지 |
| `Sp_act`는 정상이나 펌프 요청이 다르게 나감 | 스케일·펌프 선택·다축 요청 중재 |
| 펌프 압력부터 지령에 미달 | 펌프 압력제어·제한·유량·부하 |
| 펌프 압력 정상, 노즐 회로에서만 부족 | 분기 유로·밸브·실린더 |
| 노즐 회로 압력 정상이나 접촉력 부족 | 실린더 양 챔버 압력·기계적 접촉구조 |

**현재 결론:** 코드에서 *압력 지령과 완료 판정의 경로*는 확인했지만 **실제 141bar 제한의 코드상 원인을 발견했다고 말할 수 없다.** 우선 동일 시간축의 원본 지령·측정값 확보가 필요하다.
