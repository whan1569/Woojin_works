# 03. 진단 방법 제안 — 최초 노즐 터치압력 141bar 제한

> 사건 ID: NOZZLE-PRESSURE-20261030
> 상태: 진단 계획 / 현장 데이터 미수집 / 원인 미확정

## 1. 현장 시험 조건 먼저 고정

현장 담당자와 금형·레시피·유압유 온도·노즐 전진 시점·측정 위치·장비 운전 모드·압력 단위를 기록한다. **과거 175bar와 현재 141bar가 같은 조건인지** 확인한다. 비교 조건이 다르면 수치 차이만으로 부품 열화를 판단하지 않는다.

## 2. PLC 읽기 전용 TRACE 항목

| 분류 | 변수/데이터 | 목적 |
| --- | --- | --- |
| 실제 압력 | `AXdat[S_IU].Ap`, 전용 센서 사용 옵션, `PhyIn.ApDig` | 화면 압력의 실제 원본 확인 |
| 펌프압 | `AXdat[S_IU].PmpNr`, 해당 `PUdat[...].Ap` | 펌프 압력과 비교 |
| 설정 | `IU_PAR.NEG.Sp`, `SpNP`, `IU_FIX.NEG.Sptol` | 단계별 목표·완료 기준 |
| 명령 | `AXdat[S_IU].Sp_act`, `SQ_act`, `PmpReq.Req`, `PmpReq.Sp_scal/SQ_scal` | 실제 압력/유량 요구 |
| 상태 | `CtrStep`, `Status`, `SensorType`, `As`, `PhyIn.negDI1` | 어느 분기에 있었는지 판단 |
| 시험 이력 | 유온·운전 경과시간·사이클·계측 시각 | 장시간 운전 영향 구분 |

`S_IU`와 실제 화면 축 번호의 대응, 내부 압력의 0.1bar 단위를 먼저 확인한다. **전진 개시부터 최고압력 도달 직전·직후까지** 원본 데이터로 수집한다.

## 3. 유압 담당 측정

기계팀이 유압회로도 및 제조사 정비 절차로 승인한 측정 포트에서 다음을 **동일 운전 조건**으로 확인한다.

1. 메인 공급압: 해당 노즐 동작 시 형성 가능한가?
2. 노즐 분기압: 펌프 측 압력과 다른가?
3. 노즐 터치 실린더: 양 챔버 압력과 실제 이동·밀착 상태는 어떤가?
4. 릴리프/압력제어/방향제어밸브·실린더: 내부 누설/조기 개방 여부가 회로에 부합하는가?
5. 기존 체크밸브 교체 위치와 규격: 실제 고장 회로의 해당 부품이 맞았는가?

펌프 1·2 강제 펌핑 정상이라는 진술은 노즐 작동 부하 시 성능 검사의 대체가 아니다.

## 4. 원인 분리표

| 실제 관찰 | 후속 분석 |
| --- | --- |
| PLC 지령부터 낮음 | 코드·설정·STEP 판정 |
| 지령 정상, 펌프 공급압 부족 | 공급·압력제어 계통 |
| 펌프 공급압 정상, 노즐 분기압 부족 | 해당 분기 유로·밸브 누설 |
| 모든 압력 정상, 실제 밀착력 부족 | 기계적 상태·실린더 반대편 압력·접촉 구조 |
| 수치가 서로 불일치 | 센서 스케일·압력원·측정 포트 |

## 5. 완료 기준

**동일 조건에서** 압력 지령·펌프압·노즐 분기압·기계 접촉력의 차이를 설명할 수 있을 때 원인 확정 단계로 넘어간다. 아직 부품 고장/PLC 결함을 확정하지 않는다.

> 안전 조치: 유압 잔압·고온·노즐 이동 위험을 관리한다. 인터록 우회, 강제 출력, 임의 압력 상향이나 잔압 상태의 회로 분해를 진단 방법으로 사용하지 않는다.
