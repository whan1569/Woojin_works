## 1. 작업 개요

DLA5 계열 설비에서 비상정지 동작 이후 모터 Enable 상태가 정상적으로 복구되지 않아 모터를 재가동할 수 없는 문제가 간헐적으로 발생하였다.

기존에는 해당 오류가 발생하면 리셋 또는 비상정지 해제만으로는 정상 복구되지 않았으며, 설비 전체 전원을 차단한 후 다시 인가해야 모터를 재가동할 수 있었다.

간헐적으로 발생하는 문제의 특성상 현장에서 직접 원인을 확인하기 어려웠기 때문에, 사내 설비에서 동일한 조작 조건을 반복하여 오류를 재현하였다. 이후 모터 Enable 복구 과정과 관련된 프로그램 흐름을 분석하고, 실제 하드웨어의 복구 시점과 프로그램의 복구 판단 시점이 일치하지 않는 구조적 문제를 확인하였다.

이에 따라 기존의 일회성 복구 방식을 상태 기반 복구 방식으로 변경하고, 개선 프로그램을 진성기업 DLA5 1050톤 설비에 적용하여 시사출 및 실제 동작을 검증하였다.

## 2. 문제 현상

모터 Enable 오류는 주로 비상정지 동작 이후 발생하였으며, 오류 발생 시 다음과 같은 현상이 확인되었다.

* 비상정지 버튼을 해제해도 모터 Enable 상태가 복구되지 않음
* 리셋을 수행해도 모터를 다시 가동할 수 없음
* 모터 가동 명령을 입력해도 Enable 조건이 성립하지 않음
* 설비 전체 전원을 차단한 후 재인가해야 정상 복구됨
* 동일한 조작에서도 정상 복구되는 경우와 복구되지 않는 경우가 혼재함

해당 현상은 항상 발생하는 고정 오류가 아니라 하드웨어 신호의 복구 타이밍에 따라 간헐적으로 발생하였기 때문에, 단순한 조건 누락이 아닌 복구 시점과 상태 전이 간의 불일치 문제로 판단하였다.

---

## 3. 오류 재현 및 발생 조건 확인

사내 설비를 이용하여 비상정지, 리셋 및 모터 재가동 동작을 반복 시험한 결과, 다음 조건에서 모터 Enable 상태가 복구되지 않는 현상을 재현하였다.

1. 비상정지 버튼을 누른 후 해제하는 과정에서 Enable 상태가 복구되지 않는 경우
2. 비상정지 버튼이 눌린 상태에서 리셋을 수행한 후 비상정지를 해제하는 경우
3. 비상정지 해제 직후 모터 재가동을 시도할 때 Enable 조건이 성립하지 않는 경우

재현 결과, 비상정지 입력 자체보다 비상정지 해제 이후의 복구 과정에서 문제가 발생하는 것을 확인하였다.

특히 비상정지 해제 신호는 정상적으로 입력되었지만, 모터 및 드라이브와 관련된 실제 하드웨어 상태가 아직 Enable 가능한 상태로 복귀하지 않은 경우 프로그램의 복구 처리가 정상적으로 완료되지 않았다.

## 4. 기존 복구 로직 분석

기존 프로그램에서는 비상정지 버튼이 해제되는 시점을 기준으로 모터 Enable 복구 처리를 수행하고 있었다.

즉, 비상정지가 해제되는 순간 복구 조건을 한 번 확인하고, 해당 시점에 조건이 만족되면 모터를 다시 가동할 수 있는 상태로 전환하는 구조였다.

기존 로직의 개념적 흐름은 다음과 같다.

```text
비상정지 발생
    ↓
모터 Enable 해제 및 모터 상태 OFF 전환
    ↓
비상정지 버튼 해제
    ↓
복구 조건 1회 확인
    ↓
조건 만족 시 복구
조건 불만족 시 OFF 상태 유지
```

이 구조는 비상정지 해제와 동시에 관련 하드웨어 상태도 완전히 복구된다는 전제에서는 정상적으로 동작한다.

그러나 실제 설비에서는 다음과 같은 요소들이 각각 다른 주기와 시간차를 가지고 복구된다.

* 비상정지 입력 신호
* 안전회로 상태
* 드라이브 준비 상태
* 모터 Enable 피드백
* 축 제어 상태
* 통신을 통해 갱신되는 실제 상태값

따라서 비상정지 버튼이 해제되더라도 드라이브 또는 안전회로가 실제 Enable 가능 상태로 복구되기까지 일정한 지연이 발생할 수 있다.

기존 프로그램은 비상정지 해제 시점에 복구 조건을 한 번만 판단하였기 때문에, 해당 순간에 하드웨어가 아직 복구되지 않았다면 복구 시도를 놓치게 된다.

이후 하드웨어 상태가 정상으로 돌아오더라도 프로그램에서는 복구 조건을 다시 확인하지 않으므로, 모터 상태가 OFF에 고착되고 정상적인 재인가 상태로 진입하지 못하는 문제가 발생하였다.

즉, 본 문제의 핵심은 단순한 Enable 조건의 누락이 아니라 다음과 같은 **비동기 상태 간 동기화 실패**였다.

> 프로그램은 비상정지 해제 이벤트를 기준으로 복구를 판단하지만, 실제 하드웨어는 별도의 지연을 두고 복구되므로 두 시점이 일치하지 않을 경우 복구 기회를 상실한다.

## 5. 소프트웨어 개선 방향

개선의 핵심은 비상정지 해제라는 단일 이벤트에 의존하지 않고, 실제 하드웨어가 가동 가능한 상태로 회복되었는지를 기준으로 복구 상태를 결정하는 것이다.

기존 방식은 특정 순간에 조건을 한 번 평가하는 이벤트 기반 방식이었다면, 개선 방식은 복구가 완료될 때까지 현재 상태를 지속적으로 확인하는 상태 기반 방식으로 설계하였다.

### 5.1 기존 방식

* 비상정지 해제 시점에 복구 조건을 한 번 확인
* 해당 시점에 복구되지 않으면 이후 재확인하지 않음
* 하드웨어 복구 지연 발생 시 복구 기회를 놓침
* 모터 상태가 OFF에 고착될 가능성이 있음

### 5.2 개선 방식

* 비상정지 발생 시 복구가 필요한 상태임을 내부적으로 유지
* 비상정지 해제 이후 관련 하드웨어 상태를 주기적으로 확인
* Enable 가능 조건이 만족될 때까지 복구 대기 상태 유지
* 실제 복구 조건이 만족되면 모터를 재가동할 수 있는 준비 상태로 전환
* 복구가 완료되면 정상 상태 제어 흐름으로 복귀

개선 로직에서는 비상정지 버튼 해제 자체를 복구 완료로 판단하지 않는다.

비상정지 해제는 복구 감시를 시작할 수 있는 선행조건이며, 최종 복구 여부는 실제 드라이브와 관련 상태가 정상화되었는지를 기준으로 판단하도록 변경하였다.

## 6. 프로그램 변경 내용

### 6.1 복구 상태 지속 감시

비상정지 해제 순간에만 복구를 수행하던 방식을 제거하고, 복구 완료 전까지 관련 상태를 매 제어 주기마다 확인하도록 변경하였다.

개선된 개념적 흐름은 다음과 같다.

```text
비상정지 발생
    ↓
모터 정지 및 Enable 해제
    ↓
복구 대기 상태 설정
    ↓
비상정지 해제 여부 확인
    ↓
하드웨어 및 Enable 관련 상태 지속 감시
    ↓
복구 조건 불만족
    → 복구 대기 상태 유지
    → 다음 제어 주기에서 재확인
    ↓
복구 조건 만족
    → 모터를 다시 켤 수 있는 준비 상태로 전환
    → 정상 모터 가동 절차로 복귀
```

이를 통해 비상정지 해제 시점에 하드웨어가 즉시 복구되지 않더라도, 이후 실제 상태가 정상화되는 순간을 프로그램에서 감지할 수 있도록 하였다.

---

### 6.2 이벤트 기반 복구에서 상태 기반 복구로 변경

기존 로직은 비상정지 신호의 변화 시점을 기준으로 동작하는 엣지 기반 처리에 가까웠다.

개선 후에는 신호 변화 자체보다 현재 설비 상태가 복구 조건을 만족하는지를 기준으로 판단한다.

따라서 일시적인 신호 지연, 통신 갱신 지연 또는 드라이브 내부 복구 지연이 발생하더라도 복구 시점을 놓치지 않는다.

이는 다음과 같은 구조 변경을 의미한다.

```text
기존:
비상정지 해제 이벤트 발생
→ 복구 가능 여부 1회 판단

개선:
비상정지 해제 상태 확인
→ 실제 복구 조건이 만족될 때까지 반복 판단
→ 조건 만족 시 복구 완료
```

---

### 6.3 자동 재기동 방지

이번 개선의 목적은 비상정지 해제 후 모터를 자동으로 재기동하는 것이 아니다.

비상정지와 같은 안전 정지 이후 모터가 자동으로 다시 가동될 경우 예기치 않은 설비 동작으로 이어질 수 있기 때문에, 프로그램은 모터를 즉시 ON 상태로 전환하지 않는다.

복구 완료 시 모터 상태는 사용자가 다시 가동 명령을 입력할 수 있는 준비 상태까지만 복구된다.

이후 실제 모터 가동은 기존의 정상적인 가동 절차와 사용자 조작을 통해 수행된다.

```text
복구 완료
    ↓
자동 모터 기동하지 않음
    ↓
모터 가동 가능 상태로만 복구
    ↓
사용자 모터 가동 명령
    ↓
기존 정상 Enable 및 가동 절차 수행
```

따라서 이번 수정은 안전 제어 흐름을 우회하거나 자동 재기동 기능을 추가한 것이 아니라, 비상정지 이후 정상적인 재가동 절차에 다시 진입할 수 있도록 상태를 회복시키는 변경이다.

### 6.4 명령과 피드백의 역할 분리

모터 제어 과정에서 Enable 명령과 실제 Enable 피드백은 서로 구분되어야 한다.

Enable 명령은 제어 프로그램이 드라이브에 전달하는 출력이며, Enable 피드백은 명령 수행 이후 드라이브가 실제로 Enable 상태에 진입했는지를 확인하는 결과 신호이다.

따라서 피드백 신호를 Enable 명령을 출력하기 위한 선행조건으로 사용할 경우 다음과 같은 순환 의존성이 발생할 수 있다.

```text
Enable 피드백이 있어야 Enable 명령 출력
하지만
Enable 명령이 출력되어야 Enable 피드백 발생
```

개선 시에는 안전조건과 가동조건이 만족되면 Enable 명령을 출력하고, 이후 실제 Enable 피드백을 확인하여 다음 상태로 전환하도록 명령과 결과 확인의 역할을 분리하였다.

```text
안전 및 가동조건 만족
    ↓
Enable 명령 출력
    ↓
실제 Enable 피드백 확인
    ↓
정상 가동 상태 전환
```

이를 통해 Enable 명령과 피드백 간의 상호 대기 상태가 발생하지 않도록 하였다.

## 7. 현장 적용 및 검증

개선된 프로그램을 진성기업 DLA5 1050톤 설비에 적용하였다.

현장 설비에서는 모터 Enable 오류가 일시적으로 발생하는 수준이 아니라 정상 복구가 어려운 고착 상태로 확인되었으며, 하드웨어 진단 결과에 따라 모터를 교체하였다.

하드웨어 교체는 현장 설비의 물리적 이상을 해소하기 위한 조치이며, 이번 보고서의 주요 개선 대상은 비상정지 이후 Enable 복구 과정에서 발생하던 소프트웨어의 복구 타이밍 문제이다.

모터 교체 및 개선 프로그램 적용 후 다음 날 시사출과 설비 동작 시험을 수행하였다.

주요 확인 항목은 다음과 같다.

* 모터 정상 기동 여부
* 비상정지 동작 시 모터 정지 여부
* 비상정지 해제 이후 복구 상태 감시 여부
* 복구 조건 만족 후 모터 재가동 가능 여부
* Enable 오류 이후 설비 전체 전원 재투입 필요 여부
* 시사출 중 주요 설비 동작 이상 여부

검증 결과, 모터 Enable 오류가 발생한 이후에도 실제 상태가 회복되면 모터를 다시 가동할 수 있는 상태로 정상 복구되었다.

기존에는 동일한 오류 발생 시 설비 전체 전원을 차단한 후 재인가해야 했으나, 개선 후에는 전원 재투입 없이 정상적인 모터 가동 절차를 다시 수행할 수 있었다.

## 8. 개선 결과

이번 소프트웨어 개선을 통해 다음과 같은 효과를 확인하였다.

### 8.1 하드웨어 복구 지연 대응

비상정지 해제 시점과 실제 하드웨어 복구 시점이 일치하지 않더라도, 복구 상태를 지속적으로 감시하여 정상 복구 시점을 놓치지 않도록 개선하였다.

### 8.2 Enable 상태 고착 방지

일회성 복구 실패로 인해 모터 상태가 OFF에 고착되는 문제를 방지하고, 조건이 정상화되면 기존 가동 절차로 다시 진입할 수 있도록 하였다.

### 8.3 설비 전원 재투입 최소화

기존에는 Enable 오류 복구를 위해 설비 전체 전원을 차단해야 했으나, 개선 후에는 정상 조건 회복 이후 모터를 재가동할 수 있어 불필요한 설비 재부팅을 줄일 수 있다.

### 8.4 안전한 재가동 절차 유지

복구 완료 후 모터가 자동으로 재기동되지 않고, 사용자의 가동 명령과 기존 정상 가동 절차를 거쳐 동작하도록 하여 안전성을 유지하였다.

### 8.5 상태 기반 제어 안정성 향상

특정 신호가 변화하는 순간에 의존하던 제어 구조를 실제 설비 상태를 기준으로 판단하는 구조로 변경하여, 하드웨어와 소프트웨어 간의 비동기 동작에 대한 대응력을 높였다.

## 9. 최종 결론

본 문제는 단순히 모터 Enable 조건이 누락되어 발생한 문제가 아니라, 비상정지 해제 시점과 실제 하드웨어 복구 시점의 차이로 인해 프로그램이 복구 기회를 놓치는 타이밍 의존성 문제였다.

기존 프로그램은 비상정지 버튼이 해제되는 순간 복구 조건을 한 번만 확인하였기 때문에, 해당 시점에 하드웨어가 완전히 복구되지 않은 경우 이후 정상 상태로 돌아오더라도 Enable 복구가 수행되지 않았다.

이에 따라 복구 방식을 일회성 이벤트 처리에서 상태 기반 지속 감시 방식으로 변경하였다.

비상정지 해제 이후 실제 Enable 가능 조건이 만족될 때까지 관련 상태를 지속적으로 확인하고, 조건이 정상화되면 모터를 다시 가동할 수 있는 준비 상태로 전환하도록 프로그램을 개선하였다.

또한 복구 후 모터를 자동으로 재기동하지 않고 사용자의 가동 명령과 기존 정상 절차를 통해 재가동되도록 하여 안전 제어 원칙을 유지하였다.

현장 적용 및 시사출 결과, Enable 오류 발생 이후에도 설비 전체 전원을 재투입하지 않고 모터를 정상적으로 다시 가동할 수 있음을 확인하였다.

이번 변경은 단순한 오류 해제 처리가 아니라, 하드웨어와 소프트웨어 사이의 복구 시점 차이를 고려하여 상태 전이 구조를 개선한 것으로, 비상정지 이후 모터 Enable 복구의 신뢰성과 설비 운용 안정성을 향상시킨 조치이다.
