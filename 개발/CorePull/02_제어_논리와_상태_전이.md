# 02. 제어 논리와 상태 전이

## 1. 요구 동작과 현재 구현 구분

자동 운전의 의도는 형폐 완료 → 요청 보류 → 노즐터치 완료 → 실제 메인 사출 시작 → 코어 전진(사출과 병렬) → 설정 시간 만료 및 정지 확인이다. 노즐 전진 전 사출 옵션이 있으므로 단순 사출 출력 ON을 메인 사출 승인으로 사용하지 않는다.

수동 TEST는 지정된 수동 운전 조건·축 제어권을 확보한 상태에서 누르는 동안 동작을 요청하고, 버튼 해제·시간 만료·취소·인터록 발생 시 정지하는 설계다. 현재 TEST는 눌림·해제 및 사전 검사만 실장비 변수로 관측한다. 시간 기반 실제 구동 및 정상 완료는 축 제어기와 연동 후 검증해야 한다. 세팅 모드는 관측 가능하나 현재 preflight에서는 시간 기반 TEST 대상으로 허용하지 않는다.

## 2. 함수 책임

| 함수 | 역할 |
|---|---|
| CorePull_Init | Context 초기화, 시작 시 이미 눌린 요청의 실행 방지 |
| ObserveMachine | 운전 모드, 기본 조건, 형폐·노즐·사출, CO1 정지 관측, 설정 범위 |
| ObservePreflight | 모터·안전 모듈, 데이터 복사 잠금, 기존 축·Jog, 레시피·펌프 충돌 검사 |
| ObserveEdges | 최초 샘플 제외, TEST 눌림/해제 및 원시 사출 상승 에지 기록 |
| CorePull_BuildInput | 장비 관측과 기존 소유자의 승인·응답을 입력 구조체로 합성 |
| CorePull_Update | 상태 전이, 요청 ID, 타임아웃, 종료 및 재실행 제한 |

## 3. 상태 전이

| 상태 | 조건과 전이 |
|---|---|
| IDLE (0) | 어댑터 준비, 요청 해제·정지 확인 후 재무장. 새 요청의 모드와 파라미터 확인 |
| READY (1) | 파라미터 스냅샷 고정. 자동은 형폐·승인 유지와 사출 LOW→HIGH 및 노즐터치 확인. 수동은 승인·축 가용 시 시작 |
| STARTING (2) | requestId를 증가시키고 START 요청. 동일 ID의 ACCEPTED/RUNNING 기다림. 응답 누락·취소 시 STOPPING |
| RUNNING (3) | RUNNING 응답 유지, 모드·인터록·요청 확인. DONE 및 정지 확인 시 COMPLETE. 실패 시 STOPPING |
| STOPPING (4) | 동일 ID의 종료 응답(DONE/ABORTED/REJECTED)과 실제 정지 관측이 확인될 때까지 STOP 요청 유지 |
| COMPLETE (5) | 중복 시작 차단. 요청 해제·정지 및 어댑터 준비 확인 후 복귀. 자동 실패는 명시적인 resetFault 필요 |

`runTimeoutMs`는 비정상 동작 감시용 watchdog이다. 실제 Forward Time 운동 타이머를 대체하지 않으며, 밸브 ON/OFF 지연을 포함한 종료와 설정 시간의 의미는 기존 축 제어기에서 검증해야 한다.

## 4. 입력과 출력 계약

- 관측 구조체의 신호는 필요조건일 뿐 승인이나 안전 허가가 아니다. 단일 PLC 입력만으로 안전을 보장하지 않는다.
- 소유자만 ready / permit / manualAuthorized / autoRequest / mainInjectionOn / axisAvailable / stopped / feedback / feedbackId 및 시간 값을 제공해야 한다.
- 요청마다 ID를 부여하고 동일 ID의 응답만 처리한다. 오래된 응답을 새 요청의 완료로 처리하지 않는다.
- 정지 완료 이전에는 요청을 해제하지 않는다. 인터록 복구만으로 재시작하지 않고, 자동 실패 시 명시적 복구를 요구한다.
- inhibitNextMotion은 형개 등 양립 불가능한 후속 모션을 제한하도록 연결할 신호다. 현재 실제 시퀀서가 소비하지 않는다.
- 현재 `_CYCLIC`에서 gCorePullOwner를 매번 0으로 초기화하므로 어댑터 준비가 FALSE이고 상태는 IDLE에 머문다. Preflight의 OWNER 비트는 항상 켜져 있다. 임의 강제 값이나 해당 코드 삭제로 구동시키지 않는다.

## 5. 데이터 수명과 실행 주기

설정값은 사이클별로 읽고, 실행 거래가 승인되면 Context에 고정하는 구조다. 전진 시간의 내부 단위는 10 ms이고, HMI 속도/압력은 기존 스케일 사용을 전제로 한다. Task 실행 주기 20 ms는 실제 유압 제어 주기나 시간 정확도의 보증이 아니다.

관측과 실제 승인·명령 소비 간 데이터 정합성이 필요하다. 향후 생산자 → 엔진 → 소비자 순서를 결정적으로 보장하거나 검증된 일관성 있는 핸드셰이크를 구성해야 한다. 별도 Task 간 샘플링으로 인해 짧은 펄스가 누락될 수 있으며, 관측 스냅샷만으로 원자적인 제어권 확보를 보장하지 않는다.
