# FixMorph 적용 기술과 변환 원칙

## 1. 기본 변환 방식

FixMorph는 기존 FIX를 직접 수정하거나 신형 FIX 전체를 구형 데이터로 덮어쓰지 않는다.

1. 기존 장비 FIX를 값 참조 파일로 사용한다.
2. 새 모니터에서 생성한 빈 FIX를 구조 기준 파일로 사용한다.
3. 두 파일의 전체 구조체 경로와 자료형을 분석한다.
4. 경로와 자료형이 모두 같은 스칼라 값만 신형 FIX에 이식한다.
5. 신형 FIX의 구조가 유지됐는지 다시 검증한다.
6. 결과 FIX와 변경 감사 CSV를 별도로 생성한다.

## 2. 필드 비교 기준

필드는 이름만 비교하지 않고 구조체 계층을 포함한 전체 경로와 자료형을 함께 비교한다.

예를 들어 같은 이름의 필드라도 상위 구조체가 다르거나 자료형이 변경됐다면 자동 이식 대상에서 제외한다. 이를 통해 서로 다른 의미의 값을 잘못 복사하는 것을 방지한다.

분석 결과에는 다음 항목을 표시한다.

- 자동 이식할 값
- 이미 동일한 값
- 신형에만 존재하는 필드
- 구형에만 존재하는 필드
- 자료형이 변경된 필드
- 보호되어 신형 값을 유지한 필드

## 3. 보호 원칙

### 3.1 신형 구조 유지

출력 파일은 신형 빈 FIX의 다음 요소를 그대로 유지한다.

- 구조체 구성과 순서
- 필드 자료형
- 주석과 줄바꿈 형식
- 구조체 체크섬
- 신형에만 존재하는 신규 필드

### 3.2 하드웨어 입력 매핑 보호

`MA_FIX.IO.*` 영역은 신형 프로그램과 현재 하드웨어 구성을 기준으로 생성된 값이므로 구형 FIX 값으로 덮어쓰지 않는다.

해당 경로는 감사 CSV에 `KEEP_NEW_HARDWARE_MAPPING`으로 기록한다.

### 3.3 체크섬 보호

체크섬은 신형 FIX 값을 유지한다. 감사 CSV에는 `KEEP_NEW_CHECKSUM`으로 기록한다.

### 3.4 신형 전용 필드 유지

구형 FIX에 존재하지 않는 신형 신규 항목은 신형 빈 FIX의 기본값을 유지한다. 확인되지 않은 값을 추정해 자동 입력하지 않는다.

## 4. 현장 확인 항목

### 4.1 SPmotor

TH 기종은 변환 전후 `SPmotor` 값을 작업자가 확인할 수 있도록 경고한다.

- TH 권장값: `44`
- 자동 강제 변경: 하지 않음
- 실제 장착된 펌프 모터와 일치 여부를 작업자가 확인

### 4.2 SbOilHeatingValveType

TH450S 현장에서 `MA_FIX.OPT.SbOilHeatingValveType=1`이 필요한 것을 확인했다. 이 항목은 구형 FIX에 없을 수 있는 신형 신규 항목이므로 공통 필드 자동 이식과 별도로 확인해야 한다.

## 5. 출력 안전장치

- 기존 FIX와 신형 빈 FIX 원본을 덮어쓰지 않는다.
- 결과는 `FixMorph_Output` 폴더에 생성한다.
- 설비가 인식할 수 있도록 결과 파일명은 `_FIX.CSV`로 끝낸다.
- 파일명 본문은 최대 8자, 전체 파일명은 최대 16자로 제한한다.
- 같은 이름의 결과가 이미 있으면 덮어쓰지 않고 작업을 중단한다.
- 결과 FIX와 함께 이식 및 보호 내역을 담은 감사 CSV를 생성한다.
