# FixMorph 개발 진행 기록

## 1. 문제 확인

구형 모니터에서 사용하던 FIX를 신형 모니터에 적용하는 과정에서 다음 현상을 확인했다.

- FIX 또는 REC 목록 미표시
- FIX 불러오기 실패
- 재부팅 후 `Default Fix-Data Loaded` 발생
- `Invalid Recipe Data` 발생
- 포텐쇼미터 및 파라미터 초기화
- 설정 적용 후 일부 장비 동작 이상

초기에는 하나의 원인처럼 보였지만 확인 결과 두 문제로 분리됐다.

1. 구형과 신형 FIX의 구조체가 서로 다름
2. 카드 작업 후 FIX 저장소 상태 때문에 파티션 완전 초기화와 신규 설치가 필요함

## 2. 변환 방식 확정

구형 FIX 전체를 신형에 복사하는 방식 대신 다음 원칙을 확정했다.

- 신형 빈 FIX를 출력 구조의 기준으로 사용
- 전체 경로와 자료형이 같은 구형 값만 이식
- 신형 신규 필드는 신형 값 유지
- 체크섬은 신형 값 유지
- `MA_FIX.IO.*` 하드웨어 매핑은 신형 값 유지
- 원본 파일 덮어쓰기 금지
- 결과 FIX와 감사 CSV를 별도 생성

## 3. 사용자 인터페이스 구현

작업자가 두 파일의 역할을 혼동하지 않도록 입력을 구분했다.

- 기존 장비 FIX: 값 참조 파일
- 새 모니터 빈 FIX: 구조 기준 파일

파일 선택 후 기계번호, 기종, 필드 수와 구조 크기를 표시하고 두 파일을 자동 분석한다. 기종, 기계번호, 자료형 변경과 TH 기종의 `SPmotor` 경고도 표시한다.

## 4. 파일 출력 규칙 보완

설비에서 FIX 파일을 정상 인식할 수 있도록 출력 규칙을 적용했다.

- 결과 파일은 `_FIX.CSV`로 종료
- 파일명 본문 최대 8자
- 전체 파일명 최대 16자
- 기본 파일명은 생성 시각의 `월일시분(MMDDHHMM)` 사용
- 동일 파일명이 있으면 덮어쓰지 않음
- 결과 폴더와 감사 CSV 자동 생성

## 5. 현장 확인을 반영한 안전장치

### 5.1 하드웨어 매핑 유지

신형 프로그램의 `MA_FIX.IO.*` 값을 보호 대상으로 지정했다. 구형 FIX에 같은 경로가 있어도 이식하지 않고 감사 CSV에 보호 내역을 기록한다.

### 5.2 TH 기종 SPmotor 경고

TH 기종은 `SPmotor` 권장값 `44`와 이식값을 화면에 표시한다. 값은 자동으로 강제 변경하지 않고 실제 장착 모터와 작업자가 대조하도록 했다.

### 5.3 TH450S 신규 옵션 확인

TH450S 현장에서 `MA_FIX.OPT.SbOilHeatingValveType=1`이 필요한 것을 확인했다. 구형 FIX에 없는 신형 신규 항목은 자동 이식되지 않으므로 별도 확인 항목으로 관리한다.

## 6. 저장소 문제 확인과 적용 절차 보완

FixMorph로 구조체 문제를 해결해도 카드 작업 후 FIX 저장소가 정상화되지 않으면 저장 및 재부팅 문제가 남을 수 있음을 확인했다.

따라서 적용 절차에 다음 선행 조건을 추가했다.

1. FIX 저장 파티션 완전 초기화
2. 신형 소프트웨어 신규 설치
3. 신형 환경에서 빈 FIX 생성
4. FixMorph 변환
5. 저장 및 재부팅 검증

이로써 FixMorph가 담당하는 구조체 변환과 설치 단계에서 처리해야 하는 저장소 복구를 구분했다.

## 7. 현재 결론

FixMorph는 구형 FIX의 유효한 설정 자산을 신형 FIX 구조에 옮기는 도구다. 모든 문제를 파일 변환 하나로 처리하지 않으며, 카드 및 파티션 문제는 설치 단계에서 선행 해결해야 한다.

현장 적용 완료 기준은 결과 파일 생성이 아니라 다음 세 조건의 동시 충족이다.

- 신형 프로그램에서 FIX 정상 인식
- 저장 및 재부팅 후 데이터 유지
- 실제 장비 동작 정상
