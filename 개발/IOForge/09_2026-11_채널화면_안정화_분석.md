# 2026년 11월 — 채널 화면 전환 안정화 및 편집 UX 개선

> 대상: IOForge / Admin Studio  
> 구분: GUI 안정화·편집 상태 관리  
> 상태: **코드 반영 확인 / Windows GUI 반복 실행 검증 필요**

## 1. 증상 및 요구

- 채널 화면과 메인 화면을 반복 전환하면 GUI가 비정상 종료되는 현상 제보
- 채널 매핑 셀을 공백으로 만들거나 Delete를 누르면 기존 매핑을 삭제해야 한다는 요구
- 카드의 선택/편집 중/미저장/매핑 상태를 사용자가 즉시 확인할 수 있도록 시각적 피드백 개선 요청

## 2. 분석 견해 — 단일 이벤트보다 객체 수명주기 문제에 주목

반복 화면 전환에서만 발생하는 충돌은 한 번의 표시 코드보다 **동일 객체에 대한 연결·생성·해제가 누적되는 경로**를 먼저 점검할 이유가 있다. 특히 Qt Model/View에서 모델 변경 알림과 델리게이트 재생성 시점이 어긋나면 불안정성이 발생할 수 있다.

검토한 주요 원인 후보는 다음과 같다.

- 실제 데이터 변경 범위와 맞지 않는 모델 레이아웃 갱신 알림
- 탭 전환 때마다 반복되는 랙 위젯 재구축
- 채널 편집기 델리게이트의 중복 생성·연결

이 항목들은 **구조적 원인 후보 및 패치 대상**이다. 패치가 실제 모든 크래시 경로의 유일한 원인이었다고 단정할 실행 결과는 아직 없다.

## 3. 코드 반영 사항

### A. 화면 반복 전환 안정화
- 신호 강조 표시 업데이트를 적절한 데이터 역할 알림 방식으로 조정
- 불필요한 랙 화면 재생성 회피
- 채널 편집 델리게이트 재사용으로 누적 생성 억제

관련 커밋: [bab5a89a — stabilize repeated Admin Studio tab switching](https://github.com/whan1569/IOForge/commit/bab5a89a1139d96bb116c614d83e06818e9d712f)

### B. 카드 편집 상태 가시화
- 현재 선택/편집 중인 카드에 명확한 표시 제공
- 프로젝트 최종 저장 이후 변경된 카드를 미저장 상태로 구분
- 표준 로드/저장 시 편집 표시 정리

관련 커밋: [f80f71ff — show editing and unsaved status](https://github.com/whan1569/IOForge/commit/f80f71ff7cc7679b2386b32b8aad613c602be6e0)

### C. 채널 삭제 동작
- 공백 입력 및 Delete 동작에서 기존 채널 매핑을 제거하는 흐름을 반영한 것으로 기록
- 실제 저장 및 재로드 후 매핑이 완전히 제거되는지는 별도 GUI/출력파일 검증 필요

## 4. 회귀 검증 계획

| 시나리오 | 기대 결과 |
| --- | --- |
| 메인 ↔ 채널 화면 반복 전환 | 크래시·위젯 누적·성능 저하 없음 |
| 탭 복귀 후 같은 셀 편집 | 편집기 중복 생성·신호 중복 처리 없음 |
| 채널 매핑 공백/Delete | 모델에서 값 제거, 저장·재로드 후에도 삭제 유지 |
| 카드 선택·내용 수정 | 선택/편집 중/미저장 표시가 실제 상태와 일치 |
| 저장/표준 다시 로드 | 미저장 표시가 올바르게 초기화 |
| 프로젝트 출력파일 생성 | GUI 모델과 생성 파일의 매핑 결과 일치 |

자동 테스트 추가·코드 반영과 **Windows/PySide6 실GUI 반복 실행 통과**는 구분해야 한다.

## 5. 수정 설계에 대한 견해

- 모델 데이터 변경 알림과 화면 전체 레이아웃 변경 알림을 구분해야 한다.
- 위젯/델리게이트 수명주기와 소유 주체를 명확히 하는 편이 전환 시마다 객체를 새로 만드는 방식보다 안정적이다.
- 삭제/편집/저장의 상태를 하나의 프로젝트 모델을 기준으로 일관되게 관리해야 GUI 표시와 생성물이 어긋나지 않는다.
- 재현 테스트는 '한 번 정상 표시'보다 **반복 전환·편집·저장·재로드**를 묶어서 설계해야 한다.

**결론:** 안정화 및 사용성 개선 패치는 코드에 반영된 것으로 확인되며, 실제 Windows GUI 반복 조작 검증은 후속 과제이다.
