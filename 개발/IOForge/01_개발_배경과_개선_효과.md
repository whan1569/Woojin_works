# IOForge 개발 배경과 개선 효과

## 1. 개발 목적

IOForge는 생산 현장의 IO 구성 업무를 Automation Studio에서 분리해, 현장 작업자가 카드 배치와 채널 설정을 더 빠르고 쉽게 수행하도록 개발한 사내 도구다.

기존 업무는 카드 하나를 추가하거나 순서를 변경할 때도 Automation Studio 설치와 B&R 하드웨어 구조에 대한 지식이 필요했다. 카드 경로, 슬롯, 채널, PLC 변수, HW XML, IO XML과 확인용 문서를 각각 관리해야 했으며, 현장 작업자가 직접 대응하기 어려워 AS 담당자에게 작업이 집중됐다.

IOForge는 Automation Studio 전체를 대체하지 않는다. 반복 빈도가 높은 구성 작업을 별도의 경량 인터페이스로 옮기고, Automation Studio는 HW Upgrade 설치, 최종 Build와 장비 진단처럼 전문성이 필요한 범위에 한정한다.

## 2. 기존 방식의 한계

- Automation Studio를 설치해야 구성 변경 가능
- 카드 추가·삭제·순서 변경 과정이 복잡함
- 카드 채널과 PLC 변수의 반복 입력 필요
- `ConfigHW.xml`, `ConfigIO.xml`, CSV 사이의 불일치 가능
- 과거 프로젝트 복사 과정에서 기존 오류가 함께 전파될 수 있음
- 장비별 예외를 처리할 때 AS 담당자 개입 필요
- 프로젝트와 Standard의 저장·공유·이력 관리 기준 부족
- 담당자의 경험과 기억에 대한 의존도가 높음

## 3. 중앙 웹 방식과의 차이

기존에 검토·개발한 Next.js 기반 웹 방식은 중앙 관리와 강한 표준화에는 유리하다. 그러나 현재 생산 현장의 수습 속도를 따라가려면 모든 예외를 중앙 데이터 구조에 먼저 반영해야 하며, 인터넷·서버 연결과 계정·보안 운영도 필요하다.

현재는 장비별 구성이 충분히 정규화되기 전이므로, 표준을 먼저 강제하면 오히려 현장 대응의 유연성이 낮아질 수 있다고 판단했다. IOForge는 로컬에서 자유롭게 구성한 실제 프로젝트를 축적하고, 반복적으로 검증된 패턴을 이후 Standard로 승격하는 순서를 선택했다.

| 구분 | 중앙 웹 방식 | IOForge |
|---|---|---|
| 실행 조건 | 서버·네트워크 필요 | 로컬 독립 실행 |
| 현장 예외 | 중앙 형식 반영 필요 | 프로젝트에서 즉시 대응 |
| 표준화 | 사용 전 선행 | 데이터 축적 후 승격 |
| Automation Studio | 구성 담당자에게 필요 | 일반 작업자는 불필요 |
| 장애 영향 | 서버 상태가 작업에 영향 | 로컬 작업 지속 가능 |
| 공유 | 중앙 저장 중심 | 필요할 때 명시적 Push/Pull |

## 4. 도입한 기능

### 현장 구성 인터페이스

- 카드 Drag & Drop과 슬롯 사이 삽입
- 카드 추가·삭제·위치 이동
- Powerlink Node와 슬롯 구성
- 카드별 채널명·한글명·PLC 변수 설정
- 사용 신호 검색과 선택
- 프로젝트 JSON 저장·불러오기
- Standard 적용과 프로젝트별 예외 수정

### 단일 프로젝트 모델 기반 산출

하나의 프로젝트 데이터를 기준으로 다음 산출물을 함께 생성한다.

- `ConfigHW.xml`
- `ConfigIO.xml`
- `IO_info.csv`
- 프로젝트 JSON

화면, 검증과 산출물이 같은 카드·신호 정의를 사용하도록 하여 파일별 반복 입력과 기준 불일치를 줄였다.

### 관리 기능 분리

- 일반 사용자: 검증된 카드와 Standard를 이용한 프로젝트 구성·생성
- Admin: 카드·신호·템플릿·Standard 등록과 수정

일반 사용자는 생산공장과 현장 작업자를 대상으로 하고, Admin은 Automation Studio와 IO 구조를 이해하는 담당자가 사용한다. 이는 강한 보안 인증보다 오조작 방지, 책임 범위 분리와 기준 데이터 품질 유지를 위한 구조다.

### 로컬 우선 공유 저장소

- 서버와 로컬 작업공간 완전 분리
- 자동 동기화 없이 사용자 명시적 Push/Pull
- Push 전에 프로젝트 저장과 최신 산출물 재생성
- 일반 프로젝트는 프로젝트별 최신본 유지
- Standard는 사용자·시간별 이력 보존
- 일반 사용자는 Standard 조회·다운로드
- Admin은 Standard 편집·업로드

서버는 프로그램의 필수 데이터베이스가 아니라 백업·공유·수집을 지원하는 선택적 저장소다.

## 5. 개발 효과

| 기존 | 개선 후 |
|---|---|
| 전문 도구에서 수작업 | 현장 친화적 화면에서 직접 구성 |
| 카드·채널 정보를 파일별 반복 입력 | 단일 모델에서 XML·CSV 동시 생성 |
| AS 담당자에게 단순 작업 집중 | 일반 사용자와 Admin 역할 분리 |
| 현장 예외 적용을 위해 중앙 수정 필요 | 프로젝트 단위로 즉시 대응 |
| 자료가 프로젝트별로 분산 | 공유 저장소를 통한 수집 경로 확보 |
| Standard 덮어쓰기 가능 | 사용자·시간별 이력 보존 |

IOForge를 통해 전문 도구가 필요했던 반복 작업을 현장 작업자가 수행할 수 있는 범위로 전환했다. 동시에 프로젝트 데이터를 구조화된 형태로 축적해, 추후 카드 사용 패턴 분석과 Standard 개선에 사용할 수 있는 기반을 마련했다.

## 6. 기술적 영향

이번 개발의 핵심 영향은 단순한 GUI 추가가 아니다.

1. 담당자 경험에 의존하던 IO 구성 절차를 데이터와 규칙으로 표현했다.
2. 카드·채널 구성에서 XML·CSV 생성까지 하나의 흐름으로 연결했다.
3. 현장 자유도를 유지하면서 프로젝트 데이터를 수집할 수 있는 경계를 만들었다.
4. Standard를 먼저 강제하지 않고 실제 사용 데이터를 근거로 발전시키는 구조를 마련했다.
5. 일반 작업과 기술 기준 관리를 분리해 현장 작업 난도와 오조작 가능성을 함께 낮췄다.

> IOForge는 현장의 판단을 중앙 시스템으로 대체하는 프로그램이 아니라, 현장 작업자가 복잡한 Automation Studio 구성 절차를 거치지 않고 판단을 실행할 수 있게 만드는 도구다.
