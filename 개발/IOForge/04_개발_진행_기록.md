# IOForge 개발 진행 기록

## 1. 기간을 구분한 이유

IOForge는 개발 착수 당일 처음 문제를 접하고 만든 프로그램이 아니다. 개발 이전부터 현지·생산 현장 담당자와 지속적으로 소통하며 장비별 IO 구성, 카드 배열, 채널 관리 방식과 Automation Studio 작업의 불편을 수집했다.

따라서 전체 과정은 다음 두 기간으로 구분한다.

| 구분 | 기간 | 내용 |
|---|---|---|
| 사전 학습·정보수집 | 개발 착수 이전 ~ 2026-08-23 | 현장 소통, 기존 프로젝트와 IO 구성 분석, 반복 문제 축적 |
| 집중 구현·검증 | 2026-08-24 ~ 2026-08-27 | 요구 구조화, 프로그램 구현, 공유 기능, 실제 장비 시험과 문서화 |
| 배포 후 수정 | 2026-08-28 ~ 현재 | 기능 문제 수정과 사용자 편의사항 업데이트를 분리해 진행 |

5일 이내에 성과를 낼 수 있었던 이유는 문제를 단순화했기 때문이 아니라, 이전부터 축적된 현장 정보와 B&R 도메인 지식을 첫날 바로 구조화했기 때문이다.

> 정보수집에는 충분한 시간이 필요했으며, 축적된 정보를 프로그램 요구사항으로 정리하고 구현 방향을 결정하는 과정은 개발 착수 첫날 집중적으로 수행했다.

## 2026-08-28 — 카드·신호 분류와 사용 상태 표시 개선

### 카드 모델별 복수 사용처 분류

기존의 단일 카드 카테고리 대신 카드가 실제로 수용할 수 있는 신호 계열을 복수 `사용처`로 관리하도록 변경했다.

- `DI`: 디지털 입력
- `DO`: 디지털 출력
- `AI`: 아날로그 입력
- `AO`: 아날로그 출력
- `AT`: 온도 입력 계열
- `DC`: 별도 직류 계열

ATA와 AT처럼 같은 채널명을 공유할 수 있는 카드도 사용처 기준으로 묶을 수 있게 했다. 기존 카드 데이터는 새 사용처 구조로 자동 정규화해 이전 데이터와의 호환성을 유지했다.

### 현재 구성 기준 하이라이트 복구

## 2026-09-01 — Powerlink 구성과 KEB 작업 편의성 개선

### 모든 Powerlink 노드에 X20BC0083 표시

Powerlink 노드를 여러 개 생성했을 때 첫 번째 노드에서만 `X20BC0083`이 보이던 표시 방식을 수정했다.

신규 Powerlink 노드는 다음 두 필수 모듈을 명시적으로 포함한다.

1. `X20BC0083` — Slot 0
2. `X20PS9400` — Slot 1

기존 프로젝트를 불러올 때 `X20BC0083`이 누락된 원격 노드가 있으면 자동으로 추가하고 기존 모듈의 Slot을 뒤로 이동한다. 이로써 화면과 생성 데이터에서 각 Powerlink 노드의 버스 컨트롤러 구성이 명확하게 드러난다.

### Powerlink 필수 카드 보호

`X20BC0083`과 `X20PS9400`은 노드의 고정 카드로 지정했다.

- 다른 위치나 노드로 이동 불가
- 일반 카드를 고정 카드 앞쪽에 삽입 불가
- 노드 생성 시 자동 배치

### Module No. 정렬 기능 추가

사용자가 모듈 번호를 하나씩 직접 입력하지 않도록 하드웨어 구성 화면에 `Module No. 정렬` 버튼을 추가했다. 버튼을 누르면 CPU부터 각 Powerlink 노드까지 물리적인 Rack·Slot 순서로 Module No.를 자동 부여한다.

초기 구현은 1번부터 시작했으나 실제 생성 기준에 맞춰 2026-09-02에 0번부터 시작하도록 수정했다.

```text
CPU 및 Node의 물리 순서
→ 각 Rack 내부 Slot 순서
→ Module No. 0, 1, 2, 3 ... 재부여
```

Module No.를 물리 순서대로 0번부터 정렬한 생성 결과에서 각 Slot과 채널이 의도한 위치에 정상 대응하는 것을 확인했다. 이를 통해 반복적인 번호 입력을 줄이면서 생성 결과의 정합성도 함께 확보했다.

### X20 KEB 생성 편의성 추가

사용자가 KEB 적용 시 템플릿과 IO 연결을 직접 편집하지 않도록 X20 KEB 생성 기능을 보강했다. 현장에서 사용한 APC/PPC KEB 하드웨어 템플릿과 X20 `KEB_Tag1` IO 계약을 기준으로 속도 제어용 PDO 구성이 자동 생성된다.

확정된 PDO 항목은 다음과 같다.

| 항목 | Index |
|---|---|
| RelativeLoad | `0x2C50` |
| ElectricalOutputPower | `0x2C52` |
| Controlword | `0x6040` |
| Statusword | `0x6041` |
| VelocityActual | `0x606C` |
| TargetVelocity | `0x60FF` |

X20 KEB를 선택하면 필요한 속도 PDO가 적용되며, 해당 구성에 사용하지 않는 `0x2121`, `0x2510`, `0x2513`, `0x6072`, `0x6077` 기반 항목은 생성 결과에 포함하지 않는다.

IO 연결은 검증된 `gSPump[].PLK` 매핑을 유지한다.

- `ModuleOK`
- `RelativeLoad`
- `ElectricalOutputPower`
- `ControlWord`
- `Status`
- `nAct`
- `nSet`

생성된 ST3·ST4에서 정상 PDO 세트와 `ServoDrive1`, `ServoDrive2` 인스턴스를 확인했고, ST3의 OD 생성도 확인했다.

## 2026-09-02 — Module No. 정렬 결과 검증

Module No. 정렬과 신규 노드의 번호 계산을 1번 시작에서 0번 시작으로 수정했다.

- 정렬 시작값: `0`
- 모듈이 없는 구성의 다음 번호 계산 기준: `-1 + 1 = 0`
- 기존 전체 모듈의 최댓값 다음 번호로 신규 노드 필수 카드 배정

0번부터 시작하는 실제 프로젝트 기준에 맞춰 자동 정렬 결과를 검증했다.

### Slot·채널 정합성 확인

카드 구성 후 `Module No. 정렬`을 실행하고 산출물을 생성했다.

전체 모듈 번호가 물리 순서대로 0번부터 배치되고 채널 연결도 각 Slot에 정상 대응하는 것을 확인했다.

이 기능은 기존에 정상 동작하던 생성 기능 위에 사용자의 수동 번호 입력을 줄이고 번호 누락·중복을 예방하기 위해 추가한 편의 기능이다.

## 2026-09-02 — 배포 완료와 후속 수정 단계

IOForge의 핵심 기능과 실제 생성 결과 검증을 완료하고 사용자 배포를 진행했다. 배포 후 수정은 실제 생성 결과에 영향을 주는 기능 문제 수정과 작업 편의성을 높이는 사용자 최적화로 구분한다.

### 기능 문제 수정

- 생성 결과의 Module No. 시작 기준 보정
- Slot과 채널 연결 정합성 확인
- 실제 프로젝트 생성 결과 재검증

### 사용자 최적화

- 반복 입력과 수동 템플릿 편집 최소화
- 사용 중인 카드와 신호의 시각적 구분
- Powerlink 필수 카드의 자동 배치와 이동 방지
- Module No. 자동 정렬을 통한 입력 시간 단축
- KEB 선택만으로 검증된 PDO와 IO 연결 생성
- 사용자 피드백에 따른 UI와 작업 순서 개선

## 4. 개발 방식

이번 개발은 기능을 먼저 만든 뒤 현장에 전달하는 단방향 과정이 아니었다.

```text
현장 정보수집
→ 요구사항 구조화
→ 기능·설정 구현
→ 현지 적용
→ 결과 공유
→ 원인 범위 축소
→ 프로그램·매뉴얼 반영
```

현장 사용자의 실제 작업 순서를 기준으로 UI를 조정하고, 실제 장비 시험 결과를 생성 규칙과 운영 절차에 다시 반영했다. 이는 User-Centered Development와 Field-Driven Iteration을 결합한 방식이다.
