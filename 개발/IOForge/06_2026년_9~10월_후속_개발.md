## 2. 레거시 프로젝트 호환성

기존 표준 프로젝트에서 사용하던 `servo_pump`, `tag1` 등 생성 옵션을 신형 데이터 모델에서도 보존하도록 수정했다. 모션 단위에 혼재한 구형 옵션과 프로젝트 레벨의 생성 정책을 구분하여 표준 생성 시 설정이 누락되지 않도록 했다.

- 기본 제공 표준의 기존 생성 플래그 보정
- 레거시 `Tag1` / 모션 구성 회귀 테스트 추가
- 페이지 기반 예전 프로젝트 JSON 파일 로드 지원
- 표준별 XML/CSV 생성 결과 자동 확인 범위 보강

이는 새로운 옵션을 무조건 켜는 작업이 아니라 **기존에 정상 생성되던 구성을 새 데이터 구조에서도 유지**하기 위한 호환성 작업이다.

## 3. B&R Broadcast 생성 조건 수정

### 기존 문제

실제 B&R 모션이 구성되어도 과거 `servo_pump` 옵션 플래그가 빠지면 `ACP10_MC_BROADCAST` 관련 구성 생성이 누락될 수 있었다.

### 변경 기준

- B&R 모션 존재: Broadcast 관련 하드웨어 채널 생성
- B&R 모션 부재: 구형 `servo_pump` 값만으로 Broadcast를 생성하지 않음
- KEB 또는 다른 모션만 존재할 때는 B&R Broadcast 구성의 잘못된 삽입 방지

따라서 판단 근거를 **과거 설정 플래그**가 아니라 **현재 모션 구성**으로 변경했다.

### 확인

`ConfigurationGenerator.generate()` 조건과 Broadcast 회귀 테스트에서, B&R 모션 존재 시 Legacy ServoPump 값이 꺼져 있어도 생성하고 B&R 모션이 없으면 플래그가 켜져 있어도 생성하지 않는 동작을 확인했다.

> 이 확인은 저장소의 구현 및 테스트 코드 기준이다. 모든 실장비·모든 기종에 대한 현장 시험 완료를 뜻하지 않는다.

## 4. 변경관리 원칙

1. **표준 원본:** 현장 표준별 옵션과 모션 데이터의 변경을 추적한다.
2. **생성 규칙:** 프로젝트 레벨 옵션과 모션 존재 여부를 구분한다.
3. **회귀 검증:** 표준별 HW/IO/CSV 생성과 XML 파싱을 자동 검사한다.
4. **현장 검증:** 생성 파일의 문법 검사와 실장비 구성 적용 결과를 분리하여 보고한다.
5. **배포 후 기록:** 기능 문제 수정과 사용자 편의 개선을 기존 `05` 문서 체계에 따라 구분한다.

## 5. 향후 점검

- HW 교체 시에만 결과가 달라지는 사례에 대비해 생성 파일뿐 아니라 **장비에 실제 적용된 구성 및 버전 상태**를 함께 수집한다.
- 기종/옵션 표준화를 진행할 때 기본 카드와 선택 옵션 카드의 귀속을 분리한다.
- 옵션별 설계 판단과 실제 구현 여부를 동일 문서에서 명확히 표기한다.
