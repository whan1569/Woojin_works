# WMD 10004088 안전센서 작동 후 리셋 불가 현상 검토 보고서

## 1. 발생 현상

로봇이 제품 취출에 실패하여 제품이 바닥으로 낙하하였고, 낙하한 제품이 안전발판 센서를 작동시켰다. 이후 제품을 제거하고 알람 리셋을 수행해도 설비가 정상 복귀하지 않았으며, 제어기 재부팅 후에만 정상적으로 복구되었다.

일부 기종에서는 안전발판뿐만 아니라 라이트커튼이 취출물에 의해 작동하는 경우에도 동일한 현상이 발생할 가능성이 있다.

## 2. 원인 분석

현재 프로그램은 안전문이 닫힌 상태에서 안전발판 또는 라이트커튼이 작동하는 상황을 작업자의 위험구역 침입 가능성이 높은 상태로 판단하도록 구성되어 있다.

안전문이 닫혀 있음에도 내부 안전센서가 작동했다는 것은 작업자가 설비 내부에 존재하거나 비정상적인 방식으로 위험구역에 접근했을 가능성이 있으므로, 설비가 자동으로 재기동되지 않도록 복귀 조건을 제한한 것으로 판단된다.

관련 복귀 조건은 다음과 같다.

```c
if (!(MA_STAT.AbSGClosed || !MA_STAT.AbNozzleCover)
    && MA_STAT.AbMaintenance
    && !MA_STAT.AbEmStop)
{
    MC_ReadAxisError_0[i].Acknowledge = 1;
    gSPump[i].Cmd.acknowledge = 1;
    MMI_DATA.Motor.Status = S_MOTOR_STAT_START_UP;
}
```

해당 조건을 풀어보면 안전문이 열린 상태에서만 에러 승인 및 모터 재기동 경로에 진입할 수 있다.

```c
!MA_STAT.AbSGClosed
&& MA_STAT.AbNozzleCover
&& MA_STAT.AbMaintenance
&& !MA_STAT.AbEmStop
```

따라서 다음 조건에서는 기존 복귀 로직이 실행되지 않는다.

* 안전문 닫힘
* 비상정지 미작동
* 안전발판 또는 라이트커튼 작동
* 센서 작동 원인이 작업자가 아닌 낙하한 취출물인 경우

제품을 제거하여 센서 입력이 정상으로 돌아오더라도 에러 승인과 `START_UP` 상태 전환이 수행되지 않아 서보축이 `STATE_ERROR_AXIS` 상태에 남게 된다. 결과적으로 일반 리셋으로는 복구되지 않고, 재부팅을 통해 내부 상태가 초기화된 후에만 정상 복귀한다.

## 3. 설계 의도에 대한 검토

현재 로직은 안전상 잘못된 설계라기보다 위험도가 높은 상황에서 자동 복귀를 제한하기 위한 의도적인 보수 설계로 판단된다.

안전문이 닫힌 상태에서 내부 안전발판이나 라이트커튼이 작동했다면 설비 내부에 작업자가 존재할 가능성을 배제할 수 없다. 이 상태에서 센서 입력이 정상으로 돌아왔다는 이유만으로 모터를 자동 재인가하는 것은 오히려 위험할 수 있다.

다만 일부 기종에서는 로봇 취출 경로와 안전센서 설치 위치의 관계로 인해 작업자가 아닌 취출물이 센서를 작동시키는 상황이 발생한다. 이 경우에도 작업자 침입과 동일한 조건으로 처리되면서 재부팅까지 필요한 운용상 불편이 발생한다.

즉, 본 현상은 다음 두 요소가 결합하여 발생한 것으로 판단된다.

1. 안전을 우선하여 자동 복귀를 제한한 프로그램 구조
2. 취출물이 안전센서 방향으로 낙하할 수 있는 일부 기종의 구조적 특성

## 4. 코드상 해결방법

안전 기능을 약화하지 않는 범위에서 안전센서가 정상 복귀한 후 작업자의 명시적인 리셋 조작을 확인하여 에러를 해제하도록 별도의 복귀 경로를 추가한다.

권장 복귀 순서는 다음과 같다.

1. 안전발판 및 라이트커튼 정상 복귀 확인
2. 안전문 닫힘 상태 확인
3. 비상정지 정상 상태 확인
4. 작업자의 수동 리셋 입력 확인
5. 드라이브 에러 Acknowledge 수행
6. 축 Error Reset 완료 확인
7. 모터를 `START_UP` 상태로 전환

개념적인 수정 예시는 다음과 같다.

```c
else if (MA_STAT.AbSGClosed
         && MA_STAT.AbMaintenance
         && !MA_STAT.AbEmStop
         && AbSafetyMatClear
         && AbLightCurtainClear
         && AbManualReset)
{
    if ((MC_ReadAxisError_0[i].AxisErrorID == 1011)  ||
        (MC_ReadAxisError_0[i].AxisErrorID == 4005)  ||
        (MC_ReadAxisError_0[i].AxisErrorID == 6021)  ||
        (MC_ReadAxisError_0[i].AxisErrorID == 6023)  ||
        (MC_ReadAxisError_0[i].AxisErrorID == 29203) ||
        (MC_ReadAxisError_0[i].AxisErrorID == 29209))
    {
        MC_ReadAxisError_0[i].Acknowledge = 1;
        gSPump[i].Cmd.acknowledge = 1;

        memset(gSPump[i].Stat.errorText,
               0,
               sizeof(gSPump[i].Stat.errorText));

        MMI_DATA.Motor.Status = S_MOTOR_STAT_START_UP;
    }
}
```

실제 적용 시에는 발판센서와 라이트커튼의 정상 입력 변수명을 해당 기종의 I/O 구성에 맞게 적용해야 한다.

센서가 정상 복귀했다는 조건만으로 자동 재기동해서는 안 되며, 반드시 작업자의 수동 리셋 입력과 안전회로 정상 상태를 함께 확인해야 한다.

## 5. 하드웨어적 해결방법

근본적인 해결방법은 취출 실패 시 제품이 안전발판 또는 라이트커튼 방향으로 이동하지 않도록 취출 및 낙하 경로를 변경하는 것이다.

다음과 같은 구조 개선을 검토할 수 있다.

* 로봇의 취출 완료 위치 및 이동 방향 변경
* 제품 낙하 예상 위치에 가이드 또는 슈트 설치
* 제품이 안전발판 방향으로 튀거나 굴러가지 않도록 낙하 방지판 설치
* 취출 실패 시 제품을 별도의 회수 공간으로 유도
* 라이트커튼의 보호 범위를 유지하면서 제품 이동 경로와 검출 영역을 물리적으로 분리
* 안전발판과 정상 제품 배출 영역 사이에 물리적 경계 설치

안전센서의 위치 변경이나 검출 범위 축소는 작업자 보호 성능에 영향을 줄 수 있으므로 우선 적용해서는 안 된다. 취출물의 이동 방향을 제어하는 구조 개선을 우선 검토해야 한다.

## 6. 결론

본 현상은 안전문이 닫힌 상태에서 안전발판 또는 라이트커튼이 작동한 경우, 작업자 침입 가능성을 고려하여 자동 복귀를 제한한 프로그램 구조에서 발생한다.

설계 의도 자체는 안전 측면에서 타당하지만, 일부 기종에서는 취출 실패 제품이 안전센서를 작동시키면서 작업자 침입이 아닌 상황에서도 재부팅이 필요한 불편이 발생한다.

따라서 다음과 같이 개선하는 것이 적절하다.

* 단기 조치: 안전센서 정상 복귀와 작업자의 수동 리셋을 확인한 후 에러 승인 및 축 복귀가 가능하도록 별도의 코드 경로 추가
* 근본 조치: 취출 실패 제품이 안전발판이나 라이트커튼 방향으로 이동하지 않도록 로봇 취출 경로와 제품 낙하 구조 개선

프로그램 개선 시에는 자동 재기동을 허용하지 않고, 안전입력 정상 확인과 작업자의 명시적인 리셋 조작을 필수 조건으로 유지해야 한다.
