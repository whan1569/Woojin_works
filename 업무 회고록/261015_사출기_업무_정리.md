> 공개 포트폴리오용 정리문으로 고객사 식별정보·회사 고유 소스·현장 설정 원본은 포함하지 않는다.

개발 저장소: [IOForge](https://github.com/whan1569/IOForge) (접근 권한이 있는 사용자만 열람 가능).

- 카드·신호·표준 데이터 관리 기능을 구분하고 검증 및 회귀 테스트를 구축했다.
- 9월 이후 표준 프로젝트의 구형 생성 옵션을 보존하는 호환성 작업과 B&R Broadcast 생성 조건을 개선했다.
- 상세 후속 기록: [`06_2026년_9~10월_후속_개발.md`](../개발/IOForge/06_2026년_9~10월_후속_개발.md).

### 2026-10-15 HW 구성 비교 이슈 — 원인 미확정

서로 다른 HW/IO 구성 세트를 비교하는 과정에서 파일 간 차이가 작거나 같아 보이더라도 장비 적용 결과가 달랐다는 현장 피드백이 있었다. HW 구성을 교체하자 정상 동작했다는 결과는 확인되었으나, **기존 적용 HW의 원본과 당시 런타임 상태가 확보되지 않아 원인 확정은 불가**하다.

후속 검토 범위는 다음과 같다.

1. 실패 구성에서 실제 적용 중이던 HW 파일, 생성물, 버전 및 체크섬 확보
2. B&R 프로젝트의 Physical Configuration, 추가 HW 지원 항목과 Build 상태 확인
3. 파일 비교와 별개로 다운로드·초기화·장치 인식 시점의 차이 확인
4. 교체 전후 System Diagnostics를 같은 조건으로 비교

'파일이 동일하므로 원인은 없다' 또는 '특정 숨은 설정이 문제다'라고 단정하지 않는다.

## 4. 전기도면·옵션 표준화 — 진행 중

목표는 기준 사출기 구성(BASE)과 주문/기능별 옵션의 HW 카드 및 IO 신호 귀속을 명확히 구분하는 것이다. 옵션명은 개발·설계 논의에 사용한 분류명으로, 이 문서가 실제 장비별 완성된 표준을 뜻하지 않는다.

- 에너지 계측(ENG)은 기본 구성에서 분리하여 별도 옵션으로 귀속시키는 정책을 확정했다.
- 유로맵, 히터 확장, 코어백, 고속사출, QDC 등은 회로·시퀀스·채널 단위의 추가 대조가 필요하다.
- 실제 장착 카드가 존재한다고 해서 모든 장비의 공통 기본 사양으로 간주하지 않는다.
- 중복 귀속과 옵션 미선택 상태의 잔존 매핑을 점검하는 방향으로 표준을 정리한다.

**현재 상태: 표준화 검토 중.** 장비·옵션별 적용 완료 또는 최종 승인 상태로 기록하지 않는다.

## 8. 기록 원칙

- **완료:** 코드 반영·테스트·장비 검증 범위를 분리하여 기재한다.
- **확인:** 실제 관찰된 현상 또는 저장소에서 검증 가능한 변경만 기재한다.
- **추정:** 원인 가설은 별도 항목으로 둔다.
- **보안:** 공개 저장소에 고객명, 기계번호, 생산 설정 원본, 내부 회로 상세와 비공개 코드 전체를 올리지 않는다.
