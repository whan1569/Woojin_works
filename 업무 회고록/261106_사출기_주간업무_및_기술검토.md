## 종합 견해와 후속 관리 기준

### A. 검증의 층위를 구분한다
코드 조건 확인, 정적 분석 완료, 코드 변경, 실제 장비 시험, 장시간 운전 검증은 서로 다른 증거다. Nr.13은 **실장비/드라이사이클 시험 완료**인 반면, 노즐·밸브·모터 문제는 **원인 확정 또는 수리 완료가 아니다.**

### B. 공통 진단 순서를 지킨다
현상 재현 → PLC 상태/조건 확인 → I/O/드라이브 신호 추적 → 실제 전장·기계 반응 확인 → 변경점 검증 순으로 수행한다. 출력 강제나 보호 인터록 해제로 '다음 STEP으로 넘어가는지'만 확인하는 시험은 정상적인 검증으로 인정하지 않는다.

### C. 완료 처리의 경계를 명시한다
BMC 건은 **설계·자료 검토 완료**이며, 현장 회로 수정 및 가열 성능 복구를 완료했다고 기록하지 않는다. IOForge는 **패치 반영**과 **실제 GUI 반복 시험**을 분리한다.

### D. 다음 주 우선 확인
- 노즐: CtrStep, 축 Status, 자동 STEP의 동시 TRACE 확보
- 밸브: 두 출력 요구 경로와 최종 물리 DO의 동시 계측
- 모터: 최초 발생 알람과 Resolver/피드백 배선·모듈 점검 결과
- IOForge: Windows GUI 반복 전환·편집/삭제·저장 재로드 회귀시험

**총평:** 이번 주는 Nr.13 릴리즈 실기 검증과 BMC 기술 검토를 완료하고, 현장 문제 3건의 소프트웨어·I/O·전장 진단 경로를 구조화했다. 남은 사안은 실행 중 데이터와 재현 가능한 검증 결과를 기준으로 종결한다.
